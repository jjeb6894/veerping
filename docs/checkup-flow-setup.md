# Buyer to seller checkup setup

Apply `supabase/migrations/20261023040000_secure_checkup_flow.sql` before deploying this code. It revokes the old public read and update grants, adds private contact storage, and adds payment attempts. Existing requests remain in the table but their old links have no access token and cannot open the private page; create a new request after migration. Deploy the migration and app together to avoid a period where old public database policies expose new contact data.

The server needs `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, and `STRIPE_PRICE_CHECKUP`. The new live Veerping product is `prod_Vhccz8GZxOjofH`; its one-time £8.79 GBP Price is `price_1UgDNBAIfLRVSplUupAS1ir9`. Set `STRIPE_PRICE_CHECKUP` to that Price ID in the Veerping deployment. The checkout button reads its amount and currency from Stripe and verification compares the paid session against the saved Price, product, amount, currency, payer, request, and mode. Never expose the Supabase service role key to the browser. Creating this product and Price does not itself connect or deploy the website.

AutoTrader fetching, browser rendering, image copying, and Ollama enrichment are disabled in this flow. Only the submitted vehicle URL is stored and displayed; vehicle fields are marked unavailable until an authorized listing-data integration is configured. Do not scrape or republish AutoTrader listing content without permission.

The buyer can review a CSV of AutoTrader links and select specific rows to prepare. The supplied CSV contained `/car-search` filter URLs rather than individual vehicle listings, so those rows cannot become individual seller requests. This flow does not send messages through AutoTrader: no AutoTrader account or seller messaging integration is configured. The buyer's full name is not collected or shown. The draft asks to view the vehicle and includes the source link and unique seller page, but remains unsent. Do not deliver messages until an authorized AutoTrader channel exists, the deployed Stripe flow is verified, and the exact recipient list and message are reviewed.

Configure `https://templatechecklist.com/api/stripe/webhook` for `checkout.session.completed` and `checkout.session.async_payment_succeeded`. The webhook signature is checked and fulfillment is idempotent. Test with Stripe test mode and a test Price before switching the secrets and Price to live mode. Buyer and seller access links contain secret fragments; share only the seller link with the seller. A buyer who wants to pay can pay through their own private link. A seller who starts checkout is recorded as the seller payer regardless of the buyer's willingness.

The legacy general vehicle report checkout uses separate Prices and is not the Veerping viewing-request payment flow. The results screen no longer presents that legacy report checkout because its trust scores and history checks are not backed by real providers. This new Price setting applies only to the checkup request flow.
